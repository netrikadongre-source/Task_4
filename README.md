# DevOps Internship — Task 4

## 📌 Objective
This project demonstrates the use of **Git** and **GitHub** for version control following best practices,  
including branching, pull requests, tagging, and documentation.

---

## 🛠 Tools & Technologies
- **Git** (Version Control)
- **GitHub** (Remote Repository Hosting)
- **Markdown** (Documentation)

---

## 📂 Branch Strategy
- **main** — Production-ready branch.
- **dev** — Development branch where features are merged before production.
- **feature** — Feature-specific branches for isolated development.

---

## 🔄 Workflow
1. Clone the repository from GitHub.
2. Create and switch to a `dev` branch.
3. Create `feature` branches for new changes.
4. Commit and push changes to the remote repository.
5. Create **Pull Requests** to merge features into `dev`.
6. Merge `dev` into `main` after testing.
7. Tag stable releases.
